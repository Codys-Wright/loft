# Configuring Loft and writing window rules

Loft is a macOS-style shell on niri. Most of what a user changes is runtime
state that the `loft` CLI and the Settings app edit; a few install-time
choices are Nix options. Window rules are niri `window-rule`s: Loft writes the
per-app ones, the user's niri config holds the rest.

## Rules first

- **Live desktop vs. test session.** Without `--dev`, every `loft …` command
  changes the user's running desktop. That is right when the user asked for
  the change. To try something first, use a test session (end of this file),
  and point commands at it with `LOFT_SESSION=NAME loft --dev …`.
- **Never `loft windows reset` without an app id** (it drops every rule and
  the glass settings). `loft theme reset` / `loft niri reset` are just as broad.
- **Don't edit generated files**: `$LOFT_STATE_DIR/overrides/niri.kdl`,
  `$LOFT_STATE_DIR/current/*`, `~/.config/loft/niri.kdl`. Change the source
  (CLI / `niri.json` via CLI / Nix) and let Loft render.
- Window rules act when a window **opens**. After adding one, reopen the app
  or move its open windows (below).

## Where configuration lives

| Layer | Where | Changed with | Takes effect |
|---|---|---|---|
| Install-time (Nix) | `programs.loft.*` in the user's home-manager config (find it: `grep -rn "programs.loft" <their nix config>`) | edit + rebuild (`home-manager switch` / `nixos-rebuild`; on Cody's fleet `just switch` in `~/.flake`) | after the switch |
| Runtime state | `$LOFT_STATE_DIR` (default `~/.local/state/loft`) | `loft …` CLI, Settings app | immediately |
| Themes / library | `$LOFT_LIBRARY` (default `~/Documents/Loft`) | `loft theme …`, `loft library …` | on apply |
| User's niri config | `~/.config/niri/config.kdl` and its includes (often generated by Nix) | edit the source + rebuild | niri reloads |

niri include order matters, later wins: the user's config → Loft's binds → the
theme's niri fragment (`current/niri.kdl`) → Loft's overrides
(`overrides/niri.kdl`: Settings, glass, per-app window rules). So a Loft
per-app rule beats a rule in the user's config that sets the same property.

### The `loft` CLI (runtime)

`loft --help` lists everything; every subcommand has `--help`. The useful ones:

```sh
loft theme list | current | apply NAME | state      # themes; facets: loft colors|material|motion|shape|typography|icons|wallpapers|lock|launcher|sounds …
loft appearance …                                   # Transparency / Blur dials
loft windows list                                   # glass + kept-opaque apps + per-app rules
loft windows glass on|off [--focused 0.9] [--unfocused 0.8] [--blur on|off]
loft windows rule APP-ID [FIELD=VALUE…]             # per-app window rule (below)
loft niri keys | show                               # niri settings Loft manages, effective values + origin
loft niri set layout.gaps 8 · loft niri unset layout.gaps
loft niri binds                                     # every keybind, its source, what it shadows
loft niri outputs · loft niri output …              # displays (live + remembered by identity)
loft keys show | app APP … | group ID on|off          # the keyboard layer (macOS remaps via xremap), per-app fixes
loft wallpaper … · loft dock … · loft doctor perf
```

Add `--json` (for `windows`: `loft windows --json list`) for machine-readable output.

### Nix options (install-time)

`programs.loft` (Loft's home-manager module, `nix/modules/home.nix` in the
Loft repo, plus `spotify.nix`; the NixOS module is `nixosModules.default`):

```nix
programs.loft = {
  enable = true;
  niriPackage = inputs.loft.packages.${system}.niri-loft;  # per-workspace wallpapers
  theme = "default";                    # first theme; the user's choice later wins
  features = [ "spaces" "-island" ];    # defaults for Settings → Features
  workspaceIcons = { music = "󰝚"; scratch = ""; };  # bar icons per workspace name ("" = a dot)
  idle.lockAfter = 300; idle.screenOffAfter = 600;   # null = never
  qt.enable = true;                     # Dolphin etc. in the Loft look
  phone.enable = true;                  # iPhone via tether
  keyboard.enable = true;               # macOS-style remaps (xremap); seed: keyboard.{groups,apps,classes,remap}
  library = "~/Documents/Loft";
};
```

Read the module for the full list and descriptions. Runtime choices (Settings,
CLI) override Nix defaults where both exist.

**Workspace icons** (the bar's per-workspace cells, Spaces off): a named niri
workspace shows an icon guessed from its name (`src/services/wsicons.js`:
music, code, notes, comms, gaming …). To set one: Settings → Menu Bar →
Workspace Icons → Change (Nerd Font glyph or emoji; Reset returns to the
default), or by default for every machine with `programs.loft.workspaceIcons`.
Settings choices live in `$LOFT_STATE_DIR/overrides/shell.json` →
`menubar.workspaceIconMap` (lowercase name → icon) and win over Nix;
`menubar.workspaceIcons: false` turns them off (plain dots).

## Window rules

### 1. Find the app id

```sh
niri msg -j windows | jq -r '.[] | "\(.id)\t\(.app_id)\t\(.title)\t ws=\(.workspace_id)"'
```

- Wayland apps: the `app_id` the toolkit sets (GTK: the GtkApplication id;
  Qt: `QGuiApplication::setDesktopFileName`; most others: the app/desktop id).
  **When developing an app, give it a stable, unique app id** (e.g.
  `dev.cody.myapp`) so a rule can target it and nothing else.
- X11 apps (through xwayland-satellite): the app id is the WM_CLASS.
- In a test session: `loft-input -s NAME info` (or the same `niri msg` with
  the session's `NIRI_SOCKET`).

### 2. Find the target

```sh
niri msg -j workspaces | jq -r '.[] | "\(.output)\tidx=\(.idx)\tname=\(.name)"'
niri msg -j outputs | jq -r '.[] | "\(.name)\t\(.make) \(.model) \(.serial)"'
```

`open-on-workspace` takes a workspace **name**, so the workspace must be
named. Permanent names are declared in the niri config
(`workspace "code" { open-on-output "…"; }`); a running workspace can be named
with `niri msg action set-workspace-name NAME` (it names the focused one —
focus it first). `open-on-output` takes a connector (`DP-4`) or
`"Make Model Serial"`; prefer the identity, connectors can renumber.

### 3. Write the rule — `loft windows rule` (preferred)

```sh
loft windows rule dev.cody.myapp open-on-workspace=code
loft windows rule dev.cody.myapp open-floating=true default-column-width=0.5
loft windows rule dev.cody.myapp open-floating=      # FIELD= drops one field
loft windows rule dev.cody.myapp                     # show the rule
loft windows reset dev.cody.myapp                    # drop the whole rule
```

It is saved in `$LOFT_STATE_DIR/overrides/niri.json` (`window-rules`),
rendered into `overrides/niri.kdl`, validated with `niri validate`, and niri
reloads — no rebuild. It shows up in Settings → Window Rules. It matches the
app id **exactly** (`^dev\.cody\.myapp$`).

| Field | Values | niri |
|---|---|---|
| `open-on-workspace` | workspace name | `open-on-workspace` |
| `open-on-output` | connector or "Make Model Serial" | `open-on-output` |
| `open-floating` / `open-maximized` / `open-fullscreen` | true/false | same |
| `default-column-width` | 0–1 (share of the output) | `default-column-width { proportion … }` |
| `glass` | `opaque` · `custom` (own opacity) · `native` (app draws its own translucency: opacity 1 + blur) | `opacity` |
| `opacity` / `opacity-unfocused` | 0–1, with `glass=custom` | `opacity` (+ an `is-focused=false` rule) |
| `blur` | true/false | `background-effect { blur }` |
| `square-corners` | true | `geometry-corner-radius 0` |
| `block-out-from` | `screencast` · `screen-capture` | same |

Booleans also accept on/off/yes/no. Keep video, games and color-critical apps
opaque: `loft windows opaque add APP-ID`.

### 4. When to write niri KDL instead

`loft windows rule` covers one exact app id and the fields above. Write a
`window-rule` in the user's niri config when you need:

- a **regex or title** match (all dialogs of an app, one window by title,
  `is-floating`, …),
- niri properties the CLI lacks (`open-focused`, `min-width`/`max-width`,
  `default-window-height`, `default-floating-position`, `variable-refresh-rate`,
  `clip-to-geometry`, …),
- the rule to be **declarative / shared across machines** (Nix-managed config).

```kdl
// in the niri config's rules file (Cody's fleet:
// ~/.flake/modules/desktop/environment/niri/_config/rules.kdl, then `just switch`)
window-rule {
    match app-id=r#"^dev\.cody\.myapp$"#
    match app-id=r#"^dev\.cody\.myapp$"# title="^Preferences"   // any match = the rule applies
    open-on-workspace "code"
    open-focused false
    default-column-width { proportion 0.5; }
}
```

Validate before rebuilding: `niri validate -c <file>` (for an included file,
validate the entry config). See niri's wiki "Configuration: Window Rules" for
every property. Remember the order: a Loft per-app rule overrides the same
property from here.

### 5. Windows that are already open

```sh
niri msg action move-window-to-workspace --window-id ID --focus false code
niri msg action move-window-to-monitor --id ID DP-4
```

## Keyboard: when an app's keys misbehave

Loft's keyboard layer remaps keys macOS-style before apps see them: Super = ⌘
(⌘C → Ctrl+C, in terminals ⌘C → Ctrl+Shift+C), Esc / Caps Lock hold = the
window-manager key, ⌥/⌘ + arrows for word / line navigation, extras for
browsers, file managers and editors. Loft owns the keymap
(`cli/loft/keymap/mac.json`), xremap runs it (`loft-keys.service`, on with
`programs.loft.keyboard.enable`). Remaps are per **app id** (niri's), so a
misbehaving app is nearly always "Loft guesses the wrong kind of app" or "one
group fights the app's own shortcuts".

```sh
loft keys app APP-ID            # which groups reach the app (✓) and why not (·) — start here
loft keys show                  # every group (on/off), the app classes, per-app rules
```

Fix the one app, not the whole layer:

| Symptom | Fix |
|---|---|
| a terminal Loft doesn't know: ⌘C sends Ctrl+C (kills the job), ⌘V doesn't paste | `loft keys app APP --like terminals` (same for `browsers`, `fileManagers`, `codeEditors`, `jetbrains`) |
| one group clashes with the app (e.g. ⌥← / ⌘← navigation in a DAW or game) | `loft keys app APP --off text-editing` (`--on` undoes) |
| the app needs one key sent differently | `loft keys app APP --remap Super_L-k=Ctrl-k` (`--unmap Super_L-k` drops it); a per-app remap wins over every group |
| the app should get raw keys (game, VM, remote desktop) | `loft keys app APP --leave-alone` (also pauses Loft's window shortcuts there; `--no-leave-alone` undoes) |
| a group should change everywhere | `loft keys group ID on\|off\|default` |

Key names are xremap's: evdev names without `KEY_` (`a`, `Esc`, `CapsLock`,
`LeftBrace`, `F13`, `BTN_LEFT`), modifiers `Shift`, `Ctrl`/`C`, `Alt`/`M`,
`Super`/`Win`, optionally `_L`/`_R`, joined with `-` (`Super_L-Shift-t`). A
comma-separated TO is a sequence. Every change is checked before it's saved
(an unknown key or class is refused with the reason) and xremap reloads by
itself; the change is live, no restart. It applies to the focused app as soon
as xremap sees the focus, so test by switching to the app and pressing the key.

Runtime changes live in `$LOFT_STATE_DIR/overrides/keymap.json` (don't edit
it or `xremap/config.json` by hand). For a fix every machine should get, use
the Nix seed instead (`programs.loft.keyboard.apps."APP".like = [ "terminals" ];`,
`.groups`, `.classes`, `.remap`, `.extraGroups`); runtime still wins over it.
niri's own binds (Mod+…) aren't remaps: change those with `loft niri binds`
and Settings → Keyboard Shortcuts.

## `loft mcp` — the desktop as MCP tools for an agent

`loft mcp` is a Model Context Protocol server on stdin/stdout (JSON-RPC 2.0,
one message per line, protocol `2025-06-18`). An agent that runs elsewhere
(Hermes) reaches it over SSH: a forced-command launcher on the desktop machine
exports the user's session environment (`systemctl --user show-environment`:
`WAYLAND_DISPLAY`, `DISPLAY`, `NIRI_SOCKET`, `XDG_RUNTIME_DIR`,
`DBUS_SESSION_BUS_ADDRESS`) and execs `loft mcp`. Without `NIRI_SOCKET` /
`WAYLAND_DISPLAY` every desktop tool answers `isError` with the reason. Logs
(one line per call) go to stderr. `loft mcp --list-tools` prints the list.

| Tool | Does |
|---|---|
| `list_windows` (`app_id`?) · `focused_window` | id, app_id, title, workspace, output, focused, floating, size, column/row, `rect` (floating only: niri has no position for tiled windows) |
| `list_workspaces` · `list_outputs` | workspaces per output (idx, name, active, window count); displays (connector, identity, mode, logical rect, scale) |
| `focus_window` · `close_window` · `center_window` | by window id (close = the app's close request, not a kill) |
| `move_window_to_workspace` (`workspace` index or name, `focus`?) · `move_window_to_monitor` | |
| `set_window_floating` (bool) · `fullscreen_window` · `maximize_window` · `maximize_column` | the last three toggle |
| `set_column_width` (`proportion` 0.1–1) | focuses the window, then sets its column |
| `focus_workspace` · `focus_output` · `toggle_overview` (`state` toggle/open/close) | |
| `launch` (`command` argv) · `spotlight_open` | `niri msg action spawn --` in the session |
| `screenshot_output` (`output`?, `max_width`) · `screenshot_window` (`id`, `max_width`) | PNG image content (default ≤ 1920 px wide) + JSON with the logical region; a tiled or hidden window is rendered by niri (window-local image; clipboard text is put back) |
| `loft_windows_list` · `loft_windows_rule` (`app_id`, `fields`) | `loft windows …` (fields as in the table above; `null` drops one) |
| `loft_theme_list` · `loft_theme_apply` (`name`, `mode`?) | `loft theme …` |
| `loft_appearance_get` · `loft_appearance_set` (transparency, blur, terminals, gtk) | `loft appearance …` |
| `loft_niri_show` · `loft_niri_keys` · `loft_niri_set` (`key`, `value`) | `loft niri …` (set renders + reloads) |
| `loft_keys_show` · `loft_keys_app` (`app_id`, `like`/`unlike`/`off`/`on` lists, `remap` {from: to\|null}, `leave_alone`, `reset`) · `loft_keys_group` (`id`, `state`) | `loft keys …` (the keyboard layer; `loft_keys_app` with only `app_id` explains what reaches the app) |
| `shell_ipc_list` · `shell_ipc_call` (`target`, `function`, `args`) | the shell's Quickshell IPC (island, controlcenter, settings, mixer, monitor, wallpaper, timers …), only what `SHELL_ALLOW` in `cli/loft/mcptools.py` lists; arguments are checked against `quickshell ipc show` |

Not exposed on purpose: power, log out, lock, killing processes, the phone,
the clipboard, capture / recording / camera, live audio routing, and `enter`
in the bar menus. To add a shell function, add it to `SHELL_ALLOW` (the unit
test checks it exists in `src/`).

Testing: `tests/test_mcp.py` runs in `nix flake check` (framing, validation,
fake niri). Against a test session, never the live desktop:
`python3 tests/mcp_session.py NAME -- $(nix build --no-link --print-out-paths .#loft)/bin/loft`
runs `LOFT_SESSION=NAME loft --dev mcp` and exercises the tools.

## Trying it in a test session

```sh
nix run <loft checkout or github:Codys-Wright/loft>#dev -- --session NAME "$PWD" &   # headless, isolated state
until [ -f "$XDG_RUNTIME_DIR/loft-dev-NAME/session.env" ]; do sleep 0.2; done
set -a; . "$XDG_RUNTIME_DIR/loft-dev-NAME/session.env"; set +a   # NIRI_SOCKET etc. → the session's niri
echo "$NIRI_SOCKET" | grep -q loft-dev-NAME || exit 1             # never touch the live desktop
niri msg action focus-workspace 2 && niri msg action set-workspace-name code
LOFT_SESSION=NAME loft --dev windows rule dev.test.app open-on-workspace=code open-floating=true
niri msg action spawn -- foot --app-id dev.test.app
niri msg -j windows | jq -c '.[] | {app_id, workspace_id, is_floating}'
nix run …#dev -- --stop NAME
```

The `loft-drive` skill covers screenshots and input in test sessions.
